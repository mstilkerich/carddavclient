Provides a service to discover the addressbooks for a CardDAV account.

It implements the discovery using the mechanisms specified in RFC 6764, which is based on DNS SRV/TXT records and/or well-known URI redirection on the server.

discoverAddressbooks()

Discovery.php : 84

Discover the addressbooks for a CardDAV account.

public discoverAddressbooks(Account $account) : array<int, AddressbookCollection>
APIYes

The discovery may involve several servers, found via DNS SRV records, redirects or the URLs reported by the servers. If the discovery URI contains an IP address, no DNS lookups are performed; only the path given in the discovery URI and the well-known URI are tried on that server. The account's credentials are only sent to some of the servers:

  • The discovery domain is the host given in the discovery URI of the account. Credentials are sent to servers within the discovery domain, i.e. the domain itself or any of its subdomains, if they use HTTPS (or HTTP, if HTTP was explicitly requested in the discovery URI). If the discovery URI contains an IP address, only that IP address is considered to be within the discovery domain. Any port is accepted.
  • For other servers, the auth_origin_callback of the account (see Account::__construct()) decides. Without a callback, the credentials are not sent to them, and such servers will typically not be usable for the discovery.
  • Servers found via DNS SRV records are used if they are within the discovery domain. For servers outside the discovery domain (e.g. a custom domain hosted by a provider), RFC 6764 recommends that the user confirms that the server is suitable. If the account has an auth_origin_callback, the callback is asked ($targetUri is the server's URL, $baseUri the URL of the discovery domain) and the server is used only if it returns true. Without a callback, such servers are used for compatibility with earlier versions of this library.

The rules above only apply during discovery. Afterwards, the auth_origin_callback of the account is the same as before, also for the discovered addressbooks.

sortSrvRecords()

Discovery.php : 403

Orders DNS SRV records by preference according to RFC 2782.

private static sortSrvRecords(array<string|int, mixed> $records) : array<string|int, mixed>

Records are sorted by ascending priority, as lower priority values are preferred. Records with the same priority are sorted by descending weight. RFC 2782 actually requires a weighted random selection among records with the same priority; ordering by descending weight is a deterministic approximation that prefers the targets the server administrator assigned the largest share of the load to.
